# Settei 0.2.0.0 to 0.3.0.0

Precondition: this project depends on at least one Settei package. If not, report
this edge **not applicable**; do not claim the migration was applied.

1. Raise every Settei dependency used by this project to the shared 0.3.0.0 release
   together. Preserve the project's bound style and resolve its Cabal plan again.
2. Add `InvariantError` to exhaustive `ConfigError` matches. Error JSON consumers must
   accept kind `invariant`, containing rule, keys, expectation, and optional public detail.
3. Add `DeploymentContractText` and `DeploymentContractJson` to exhaustive
   `DiagnosticMode` matches. The new flags are mutually exclusive with existing diagnostics.
4. Replace schema/load/resolve and schema/contract/load/validate dispatch with
   `prepareDiagnostic mode schema contractSupport`. Exhaustively handle
   `DiagnosticRejected`, `DiagnosticRendered`, and `DiagnosticNeedsRuntime`. Load files,
   read environment or credentials, validate supplied names, resolve, and run validators
   only in `DiagnosticNeedsRuntime token`. Pass that same invocation's token to
   `resolutionDiagnostic` or, after `validate`, `validatedDiagnostic`.
5. Both runtime helpers now return `DiagnosticDecision`, renamed from the unreleased
   `ValidatedDiagnostic`. Exhaustively handle its unchanged constructors
   `DiagnosticFailure`, `DiagnosticOutput`, and `DiagnosticContinue`. Only successful
   `DiagnosticContinue` may start resources or normal application work. The helpers
   check resolution/validation success before printing `configuration valid`.
6. For validators, preserve the two-document JSON explain failure convention: errors
   then validated resolution with invariant outcomes, each newline-terminated on stderr.
   Base resolution failures leave rules not run. Successful validated JSON is one stdout
   document. Bare resolution JSON explain failure retains text errors then resolution
   JSON. Keep warning routing on success and suppress warnings on failure.

Supply `Just (deploymentContract inputs config)` only with the application's actual
bindings, explicit built-in sources, and optional profile for the same declaration.
This is a lazy static result. `Nothing` declares omitted support and rejects either
contract flag with fixed plain text `deployment contract diagnostic is unavailable\n`
before runtime work. Reference routing is exit 4, empty stdout, and stderr, including
JSON mode. Partial `schemaDiagnostic` and `contractDiagnostic` remain renderers;
`Nothing` from them is never startup permission.

The checked token permits runtime resolution, not startup. Never cache a normal-mode
token and use it for another invocation. Do not restore the unchecked composition, pass
`Just` a contract built from wrong inputs to silence the compiler, add a public switch
to disable contract support, or log the typed configuration.

## Dispatch migration

Before (unsafe selector composition; shown only to identify code to replace):

```haskell
case schemaDiagnostic mode schema of
  Just output -> emit output
  Nothing -> do
    result <- acquire
    case resolutionDiagnostic mode result of
      Just output -> emit output
      Nothing -> startResolvedApplication result
```

After (compiles against public modules):

```haskell
import Data.List.NonEmpty (NonEmpty)
import Data.Text (Text)
import Settei
import Settei.Optparse

-- The caller owns stream routing, exit policy, and warning reporting.
dispatch :: DiagnosticMode -> Schema -> Maybe (Either (NonEmpty ConfigError) DeploymentContract) -> IO (ResolveResult a) -> (a -> IO ()) -> IO (Either Text Text)
dispatch mode schema contract acquire startup =
  case prepareDiagnostic mode schema contract of
    DiagnosticRejected problems -> pure (Left problems)
    DiagnosticRendered output -> pure (Right output)
    DiagnosticNeedsRuntime runtimeMode -> do
      result <- acquire
      case resolutionDiagnostic runtimeMode result of
        DiagnosticFailure problems -> pure (Left problems)
        DiagnosticOutput output -> pure (Right output)
        DiagnosticContinue config -> startup config >> pure (Right mempty)
```

Applications keep ownership of streams, warnings and exit codes. The example returns
text dispositions for routing by the caller; preserve existing source-load exit 3 and
configuration rejection exit 4 in applications using those conventions. Applications
with invariants call `validate` inside the runtime branch and replace the final helper
with `validatedDiagnostic token validated`, preserving the same exhaustive decision match.

## Verify in the consumer

Run the project's build and tests. Then invoke its executable with both
`--describe-config-json` and `--deployment-contract-json`, a missing configuration path,
and no runtime credentials. With contract support supplied, both must exit 0, render
version-1 `settei.schema` or `settei.contract`, and never start application work. If this
consumer intentionally supplies `Nothing`, contract mode must instead exit nonzero with
the fixed unavailable message before reading inputs. Test text flags as well.

Instrument input acquisition and startup independently where possible. Normal valid
execution should acquire once and start once; check and explain acquire once and never
start. Missing/decode/invariant failures must never start or announce check success.
Scan output for a unique secret sentinel, including its ASCII marker to catch escaped
representations. Summarize changed call sites and actual validation results.
